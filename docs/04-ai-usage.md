## 2. AI 生成内容里被我改掉的部分

挑有代表性的五处，它们最能体现"review 是否真的发生"：

### (1) `auto` 模式的降级策略

AI 初稿在拿不到 Key 时直接返回 mock，**不写任何标记**。
我改成把 `provider` 写进运行输出，并在 `.env.example` 里注明。
理由：这道考题明确 Mock 与真实的边界必须写明，静默降级等于制造假证据。

### (2) 重试的语义边界

初稿把"模型返回非法 JSON"与"工具调用失败"混在同一套重试里。
这会直接踩到考核的红线 —— 规则原文的"自动重试"不计入 ReAct。
我把重试收窄到**只修格式**：空内容、非法 JSON、动作名越界。
业务动作（换时段、请求确认、保存）一律不由代码替模型决定，
并在 `llm.py` 文件头注释里把这个界限写死，防止评审误读。

### (3) 幂等指纹的粒度

AI 初稿把整个 `action_input` 做指纹，包括模型生成的自由文本 `note`。
实测导致重复提交被误判为冲突，**直接违反题目验收点**。
我改成只取 `(material_id, slot, confirmed)`，理由和证据见 `02-solution.md` D3。

### (4) 最终保存状态听模型的

初稿把 `finish` 里的 `draft_status` 直接透传。
这意味着模型只要自称 saved，输出就是 saved —— 而这恰好是题目列出的关键缺陷
"虚报保存成功"。我改成以 `trace` 里是否有成功的 `save_draft` 为准，
不一致时强制改写并记入 `failures`。

### (5) 工具返回值不进 conversation

初稿把工具结果写进了 state 的一个字段，没写回对话列表。
那样模型下一步根本看不到上一轮的观察，所谓 ReAct 会退化成"按脚本串行调用"。
我改成 `observation_message()` 追加到 `conversation`，
并在测试里断言 `19:00` 这个只在 `query_slots` 返回值里出现的字符串出现在对话中。

## 3. 我的独立验证

不是"AI 说它跑了"，是我自己复跑的：

| 验证项 | 方式 | 结果 |
|---|---|---|
| 真实模型可用 | `scripts/check_llm.py` | Key 生效，返回合规 JSON 动作 |
| 模型确实会因观察不同而改动作 | `scripts/probe_decision.py`，三组不同的工具返回 | 产出三条不同路径，理由各不相同 |
| 六个必验点 | `scripts/run_examples.py` 真实模型，逐条读 `output.json` | 全部通过，见 `03-evaluation.md` |
| 未完成状态 | `--max-steps 2`，检查退出码 | `MAX_STEPS_EXCEEDED`，退出码 `2` |
| 幂等 | 同 request_id 连跑两次，比对 `draft_id` 与 `total_drafts` | 同一草稿，总数 1 |
| 越权发布不可能 | 断言工具注册表 + 文本扫描 | 无 publish 入口 |
| 全部测试 | `pytest` | 43 passed |
| 离线可复现 | 移除 Key 后重跑测试 | 依然 43 passed；`examples/mock/` 无需 Key 即可重新生成 |

## 4. 哪些部分根本没有 AI 的影子

坦白说很少，但以下判断是在 AI 之外的：

- **选题**：第 1 题的高分依据可以用代码保证，第 3、4 题依赖模型生成质量 —— 这个判断决定了整个项目的可控性。
- **"工具集里不存在 publish"作为架构设计而非提示词约束**：来自 OWASP 的 mitigation 顺序，也不是 AI 的建议。
- **主动写明 Mock 边界**：这是"主动给出自己的限制"，AI 初稿里没有。
- **录入失败用例（F1~F5）**：AI 不会主动记录自己犯的错。

## 5. 一句自评

我用 AI 的方式是**当它写一个我不署信任的实习生**：产出要快，但每一处都过我的手，
尤其是涉及"不可撒谎"的地方（保存状态、失败上报、Mock 边界）。
这道题在我看来就是考这个 —— 能否对自己没写过的代码负责。
